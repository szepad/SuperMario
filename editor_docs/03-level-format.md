# 3. The `.lvl` format

Two formats exist:

- **v2** (current): written and read by `LevelFormat` (`Source/Game/Level/LevelFormat.cs`).
- **Legacy** (pre-rewrite): only *read*, by `LegacyLevelParser`, to migrate old files.

All levels in `levels/` are v2.

## 3.1 A complete v2 file

This is `levels/bonus01.lvl` in full:

```
MARIOLVL 2
size 16 14
background Underground
music Underground
time 400
pipe_intro false
spawn 40 32

def a brick item=None hidden=false palette=Underground
def b tile 32 solid
def c coin
def d tile 26 solid
def e tile 27 solid
def f tile 28 solid
def g tile 34 solid
def h tile 35 solid
def i tile 36 solid
def j auto underground
grid
.*16
a .*3 a*7 .*4 b
a .*14 b
a .*14 b
a .*4 c*5 .*5 b
a .*14 b
a .*3 c*7 .*4 b
a .*14 b
a .*3 c*7 .*4 b
a .*3 a*7 .*4 b
a .*3 a*7 .*2 d e f
a .*3 a*7 .*2 g h i
j*16
j*16
end

entity warp_pipe 200 192 dest="" tag=bonus01 dir=Right return_to_parent=true
```

Its legacy original was 4.5 KB of `simple,-1,False,;anim,Mario2.BrickTile,0,False,1;…`. The v2 file is 589 bytes and reads like a picture of the room.

## 3.2 Lexical rules (the tokenizer)

Every line is split into **tokens** by `LevelFormat.Tokenize`:

- Whitespace separates tokens. Blank lines are ignored. `\r` is stripped, so CRLF files work.
- **Comments:** a `;` at the *start of a token* (outside quotes) ends the line. `; whole-line comment` and `size 16 14 ; trailing comment` both work. A `;` in the middle of a token is a literal character.
- **Quotes:** `"` starts a quoted section anywhere in a token and the quote characters themselves are dropped, so `dest="my level.lvl"` is the single token `dest=my level.lvl`. Inside quotes, `\` escapes the next character (`\"` → `"`, `\\` → `\`). An unterminated quote is an error.
- **key=value:** split at the *first* `=`, so values may contain `=`.

The writer quotes a value when it's empty or contains whitespace, `"`, `\` or `;`, and escapes `\` and `"`. That's why an empty tag is written `tag=""`.

## 3.3 Records

The first non-blank line must be the header **`MARIOLVL <version>`**. A version greater than 2 is rejected ("saved by a newer version"). Every following line starts with a record keyword:

| Record | Syntax | Notes |
|--------|--------|-------|
| `size` | `size <width> <height>` | height **must** be 14, width 16–4096. Must come before `grid`. |
| `background` | `background <WorldBackground>` | enum name: `Sky`, `Underground`, `Castle`, `Water`, `Night`, `Black`, `Waterfall` |
| `music` | `music <MusicName>` | enum name, e.g. `Overworld`, `UndergroundIntro` |
| `time` | `time <int>` | starting timer |
| `pipe_intro` | `pipe_intro true\|false` | play the 1-2 style pipe intro before the level |
| `spawn` | `spawn <x> <y>` | where the player's **feet** (bottom-centre) start, in texture pixels |
| `def` | `def <code> <tile spec>` | defines a legend code (see 3.4). Codes are unique; `.` is reserved for air. |
| `grid` … `end` | 14 row lines between them | see 3.5. Only one grid. |
| `entity` | `entity <key> <x> <y> [prop=value ...]` | see 3.6 |

Missing meta records fall back to `LevelMeta.Default`. **Unknown records** are skipped with a warning, which leaves room to add records later without breaking older builds that ignore them.

## 3.4 Tile specs (`def`)

| Spec text | `TileSpec` |
|-----------|------------|
| `tile <id> solid` / `tile <id> passable` | `SimpleSpec(id, solid)`. Solidity is always explicit. |
| `auto <group>` | `AutoSpec` of `grass`, `underground`, `tree`, `tree_trunk`, `castle_floor`, `grass_decor` |
| `question item=<ItemType> hidden=<bool>` | `QuestionSpec` (both keys optional; defaults `None`, `false`) |
| `brick item=<ItemType> hidden=<bool> palette=<TilePalette>` | `BrickSpec` (keys optional) |
| `coin`, `grass_left`, `grass_middle`, `grass_right`, `lava`, `lava_bottom` | `AnimSpec` |

An unknown kind or autotile group becomes **air with a warning**, not an error. One bad definition shouldn't make a whole level unloadable.

**Legend codes** are generated by the writer in order of first appearance (row by row, left to right), skipping air: `a`…`z`, `A`…`Z`, then `aa`, `ab`, … (a bijective base-52 count). The reader accepts any token as a code, so a hand-written file can use descriptive codes like `def ground auto grass`.

## 3.5 The grid

Exactly 14 lines between `grid` and `end`, top row first. Each line is a list of **runs**: `code` (one cell) or `code*N` (N cells). `.` is air. Each row must add up to exactly the level's width, otherwise reading fails with the row's line number. An unknown code is an error.

## 3.6 Entities

```
entity warp_pipe 928 128 dest=levels/bonus01.lvl tag="" dir=Down return_to_parent=false
```

- `key` must exist in `EntityCatalog`. Unknown entities are **skipped with a warning**.
- `x y` = the entity's **feet** (bottom-centre of its box, `Entity.Feet`) in texture pixels. An entity standing on a tile has its feet on that tile's top edge, centred: a Goomba in column 20 standing on row 12 is at `328 192`.
- Properties are matched against the entity's schema. Each schema property is **normalized** (`TryNormalize`), invalid values fall back to the default with a warning, and unknown property names are dropped with a warning. A loaded placement therefore always has *every* schema property, in canonical form.
- The writer emits properties in **schema order** (then any unknown leftovers), which keeps diffs stable.
- Entity order is preserved. It's the order entities are spawned in, and the order they're drawn within the same layer.

## 3.7 Errors and warnings

- **Errors** throw `LevelFormatException`, whose message starts with `Line N:`. Examples: bad header, wrong height, a malformed row, a duplicate code, a number that isn't a number, missing `end`. The game's `LevelLoader.Load` turns these into a console message and a `null` world. The editor shows them in a dialog.
- **Warnings** go into the optional `warnings` list: unknown records, kinds, entities or properties, and invalid property values. The editor shows them after opening, and the game prints them.

## 3.8 Writing and saving

- `LevelFormat.Write(level)` → string. Numbers use the invariant culture (no `1,5` on a Hungarian locale).
- `LevelFormat.Save(level, path)` writes `path.tmp` and then **moves it over** the target. A crash mid-write can't leave a half-written level behind.
- Round-tripping is exact: `Write(Read(Write(level))) == Write(level)`. This was checked for every shipped level during migration.

## 3.9 The legacy format

Read-only, by `LegacyLevelParser.Parse`. For reference:

```
16;1;36;18;2;False;400                              ← cols;background;spawnX;spawnY;music;pipeIntro;time
simple,-1,False,;anim,Mario2.BrickTile,0,False,1;…  ← 14 rows; every cell ends with ';'
…
Mario2.WarpPipe;192;176;,bonus01,1,True             ← Type;x;y;customData
```

- **Meta:** enums are stored as **integers** (that's why reordering `MusicName` used to be dangerous).
- **Cells:** `simple,<id>,<collidable>,<data>` (id `-1` = air) or `anim,<CLR type name>,<data…>`. Question data is `item(int),hidden`, brick data is `item(int),hidden,palette(int)`.
- **Positions:** the old format stored `Entity.Position` for the player and every entity. The parser converts each one to feet with `EntityMetrics` (`Source/Game/Level/EntityMetrics.cs`). It measures each entity's `Size`/`SizeOffset` once per property set, because a platform's size depends on its `size` property.
- **Entities:** the CLR type name plus a type-specific string that each entity used to produce in its own `SaveCustomData`. The parser now holds those decoders in one place:

| Legacy type | Data | Becomes |
|-------------|------|---------|
| `Mario2.Goomba` / `Mario2.Koopa` | palette name | `goomba`/`koopa` `palette=` |
| `Mario2.RedKoopa` | (ignored) | `red_koopa` |
| `Mario2.RedFlyingKoopa` | tile offset × 10 as int | `red_paratroopa tile_offset=` (÷10) |
| `Mario2.Firebar` | `Length,IsGoingRight` | `firebar length= clockwise=` |
| `Mario2.ConstantPlatform` | `Type,Dir` | `platform_constant size= direction=` |
| `Mario2.PingPongPlatform` | `Type,IsHorizontal,offset×10` | `platform_pingpong size= horizontal= tile_offset=` |
| `Mario2.WarpPipe` | `dest,tag,dir(int),returnToSubworld` | `warp_pipe dest= tag= dir= return_to_parent=` |
| `Mario2.WarpExit` | tag | `warp_exit tag=` |
| `Mario2.Bowser`, `Axe`, `Toad`, `Midway`, `NoPlant`, `Flagpole`, `CastleEntrance` | – | same-named keys |

### Autotile promotion

Legacy files store *resolved* pieces ("grass top-left", tile 0), not "grass". Converting them as plain tiles would give a level that looks right but no longer auto-tiles. Dig a hole into 1-1's ground and the edges wouldn't fix themselves. So after parsing, `PromoteAutotiles` runs:

1. Build a map from every autotile *output* spec to its group (`SimpleSpec(0, solid)` → grass, `AnimSpec(GrassLeft)` → grass_decor…). The groups' outputs don't overlap, so the map is unambiguous.
2. **Optimistically promote** every cell whose spec is in the map to `AutoSpec(group)`, remembering the original.
3. **Verify:** resolve each promoted cell. If the result differs from its original, revert that cell to the original.
4. Reverting changes what neighbours see, so **repeat step 3 until nothing changes**. It always terminates, because cells only ever leave the promoted set.

The result looks **identical** to the original, guaranteed, because every promoted cell resolves to its original piece. Everything that *can* be an autotile is one. For example, in 1-1, 441 of 649 non-air cells became autotiles. The rest are pieces placed in ways the rules wouldn't produce, like a bush end touching a pipe.

## 3.10 Migration

```bash
dotnet run -- --migrate-levels levels               # from the project folder; writes levels/*.lvl.bak backups
dotnet run -- --migrate-levels levels --no-backup   # when git is your backup
dotnet Mario2.dll --migrate-levels <folder>         # from a published build
```

- `Program.Main` makes path arguments absolute (`CommandLine.ResolvePaths`) *before* switching the working directory to the game folder, so relative paths mean "relative to where you ran the command".
- Any argument starting with `--` puts the game in command mode. The window is created hidden (assets need an OpenGL context), the command runs, and the game exits.
- Files already in v2 print `up to date`. Failures are listed per file and don't stop the rest.
- Without a folder argument the game's own `levels` folder (next to the executable) is used.

How the shipped levels were verified: before the old loader was deleted, a temporary command loaded every level both with the old `WorldLoader` and via legacy → v2 text → v2 reader → `LevelBuilder`. It compared the two `World`s:
- per cell: tile type, id, solidity, item/hidden/palette data and collision excludes;
- per entity: type, position, size, custom data and sprite sheet.

All 9 levels matched exactly.

**Feet coordinates.** v2 files first stored `Position`, like the legacy format. Entity and spawn coordinates were then switched to feet once, deliberately *without* a format version bump or compatibility code. The shipped levels were converted once, by re-migrating their legacy originals (still in git history) with the feet-aware parser. A temporary check then built every converted level and compared each entity's runtime `Position`, and the player spawn, with the numbers in the previous files: 97 of 97 matched. A v2 file written before that switch would load with its entities slightly shifted.

## 3.11 Changing the format later

- **Additive changes** (a new optional record, a new entity property with a default, a new tile kind) need no version bump. Old files lack the new data and get defaults. Older builds reading new files warn and skip what they don't know.
- **Breaking changes** (changing what an existing field means): bump `LevelFormat.Version`, keep reading the old version in `Read` (branch on the header's version), and always write the newest.
- **Renaming an entity key, property key or enum member** breaks existing files. Either don't, or accept the old name in the reader.
